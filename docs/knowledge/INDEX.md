# 프로젝트 지식 갱신

기록 상태는 **관찰됨**(보고·관찰), **가설**(원인 후보), **확인됨**(재현·근거), **승인됨**(적용 범위를 사용자가 확정), **폐기됨**(대체 규격이나 이유를 링크)이다. 판단에 쓴 커밋·테스트·재현 입력과 다시 검토할 조건을 함께 기록한다.

| 바뀐 사실 | 갱신 위치 |
| --- | --- |
| 슬롯·바인딩·피부 가림 | [의상 계약](../../src/entities/character/clothing/README.md) |
| 리그·저장·에셋 등 호환 계약 | [계약](../contracts/) 및 영향 받는 테스트 |
| 승인된 모델·스타일·UI | [선례](../references/INDEX.md), 기존 [UI/UX 지침](../UI_UX_DESIGN_GUIDELINES.md) |
| 확인된 버그 원인·퇴역 규격 | 아래 실패 기록에 조건·근거·대체 방식, 관련 회귀 검증 링크 추가 |
| 구현·통합·일시적 장애 | [현재 상태](../core/CURRENT_STATE.md), 작업 기록 또는 아래 알려진 범위 |
| 사용자 공통 기준 교정 | 해당 분야 지침에서 승인 범위를 갱신 |

확인된 기술적 사실과 구현 상태는 작업자가 갱신한다. 세계관, 아트 방향, 핵심 게임 목적 또는 비호환 계약 변동은 사용자 결정과 적용 범위를 기록한다.

### 카엘 계단 측면 투시 (2026-11-25)

`e79736d`의 카엘 계단 절개는 지형 표면을 `discard`하고 절개 수직면을 렌더 메시로 만들지 않아 그 자리의 깊이가 비었다. `9403d8c`에서 지형 경계 메시만 끄면 같은 구멍이 재현된다. 지형 `discard`를 끄면 원래 지형이 계단 통로 쪽으로 튀어나와 깊이를 기록한다. 두 커밋 모두 near를 0.20m에서 0.02m로 줄여도 판정이 바뀌지 않았다.

카엘의 실제 생성 지형·건축과 `Player.advance`·`CameraRig.update`로 얻은 1인칭 시점 30개를 Mesa llvmpipe의 780×360, 24비트 깊이 버퍼에서 비교했다. 옆보기 기준 yaw ±25°, pitch 0°·−20°·−39°를 포함했다. 경계 메시를 켠 main에서 28개 시점의 측면 픽셀이 더 가까운 깊이를 얻었다. 예를 들어 카메라 `(406.928, 48.172, -449.760)`, yaw 0°, pitch −20°의 중앙 픽셀은 기존 깊이 버퍼의 초기값에서 지형 경계의 약 2.36m로 바뀌었다. 장면에는 계단과 인근 지형·건축을 렌더했다.

`9403d8c`의 잔여 틈은 같은 실험의 6개 시점에서 확인했다. 지형과 경계가 공유하는 재질의 discard 분기에서 경계 프래그먼트가 잘렸다. 경계 재질에서만 절개 마스크를 제거한 뒤 30개 시점 모두 경계에 마스크를 끈 대조군과 깊이 버퍼가 일치했고, 기존에 잘리던 시점에서 최대 185픽셀의 경계 깊이가 복구됐다. [실월드 회귀 검증](../../tests/world-playability.mjs)은 지형의 절개와 경계의 깊이 쓰기 조건을 확인한다. Chromium 전체 게임 화면과 사용자 기기는 미검증이다.

## 알려진 검증 범위

- [공통 의상 런타임](../../src/entities/character/clothing/README.md)의 여성 극단 포즈 목표 미충족은 일반 포즈와 구분한다. [간격 진단](../../tests/garment-alignment.mjs)은 수치를 기록하며 피부 간섭 전체를 판정하지 않는다. 기준 `2d3d488c`의 여성 왼쪽 전완 중단에서 게임 IK 시 최저 약 −29mm의 signed gap을 측정했다. 자동 추적이 통과해도 의상 품질의 미검증 범위로 남긴다. 리그나 가림 변경 때 양쪽 체형의 굽힘·비틀기·실제 게임 IK에서 다시 본다.
- 실기기별 FPS 및 PWA OS 설치는 작업별 환경에서 확인한다. 저장소의 생태 기획 전체에 대한 에셋 등록 상태는 아직 목록 단위로 확인해야 한다.

- Chromium의 모바일 터치 시뮬레이션에서 지도 드래그 뒤 닫기 버튼에 pointerup과 touchend가 들어왔지만 호환 click이 빠진 사례를 확인했다. [모바일 회귀](../../tests/mobile-regression.mjs)는 단독 터치 닫기, 드래그 포인터 해제와 실제 닫기 클릭을 검사하고 직후 터치 닫기는 PARTIAL로 기록한다. 실기기에서도 같은지 별도 재현이 필요하다.

## 인프라 후속 검수

0eedd8b의 시험 장착물은 머리 본 100% 강체 모자와 머리띠였다. 의상 전체 변형의 일반화 증거로 사용할 수 없다. 후속 작업은 승인 원본을 보존한 소매 파생 시편 두 종류로 다중 본 경로와 전체 참조 정점/에지 계측을 추가한다. 피부 간격과 실제 신상품 품질은 미검증이다. 원격 Actions의 성공과 직접 브랜치 Pages 게시 경로가 공존하므로 게시 Source 확인 전에는 실패 빌드 차단을 보장하지 않는다.

### 카메라 계단 추적 및 압축 (2026-11-25)

사용자 관찰: 계단에서 수직 떨림, 낙하·엉킴 시 플레이어 내부가 보임. `ae89146` 코드에서 floor-clamped renderPos에 3인칭 높이를 ±0.10m/30s⁻¹로 붙이고 충돌 boom을 최소 0.05m까지 축소하는 경로를 확인했다. 1인칭은 애니메이션 머리 자세를 직접 더했다. 카메라 전용 높이 상태(8/14s⁻¹, 최대 0.42m 추적 지연), 완만한 머리 오프셋, 실제 near-plane 코너 및 몸체 여유를 검사하는 boom을 적용한다. 공간이 부족하면 현재 CameraRig 눈 시점으로 일시 전환하며 저장 모드와 물리를 보존한다. [합성 회귀](../../tests/camera-comfort.mjs): 계단 단차, 정착, 텔레포트, 프레임률, 벽, 복귀, 피치/종횡비. 합성 함수 검증만 수행했으며 실제 카엘 계단·낙하 및 Chromium/실기기 품질은 미검증이다.

### 회전된 물체 모서리에서 이동 정지 (2026-11-25)

기준 `f47fd94`: 원형 플레이어 접촉 반경 자체가 아니라 `Player.tryMove`가 이분 탐색으로 최초 접촉 위치를 찾은 뒤에도 전체 이동 끝점의 법선을 사용했다. 회전된 1m 상자(yaw 0.3rad) 모서리로 달리는 합성 재현에서 기존 진행 거리가 약 1.25m에 그쳤다. 최초 blocked probe의 접촉 집합·법선으로 잔여 이동 및 속도를 투영하도록 수정한다. 반경, 단차, 중력, 수영 및 카메라는 변경하지 않는다. 기존 긴 벽 테스트는 벽 끝에서도 X축 이동 정지를 요구했으므로 벽 옆 비관통을 매 프레임 검사하고 벽 끝 이후 탈출을 요구하도록 바로잡았다. [회귀](../../tests/player-physics.mjs): 기존 물리/카엘 충돌 fixture 및 4개 각도 모서리 통과 검사. 실제 코드와 Three 벡터를 사용한 JS 격리 실행(로더의 AbortController만 대체) 통과. 전체 브라우저 및 실기기 체감은 미검증.

### 이동 방향 카메라 자동 정렬 (2026-11-25)

기준 `bbb7b8cf73`: 캐릭터의 bodyYaw는 실제 이동 방향으로 회전하지만 CameraRig는 player.yaw(수동 입력)만 추적해 이동 자동 정렬 자체가 연결되어 있지 않았다. 3인칭 지상에서 시선과 이동 방향이 100° 이상 어긋나면 최대 3.2rad/s로 돌아온다. 자동 회전 중 조이스틱/키의 이동 기준을 해당 입력 구간에 고정하여 이동 경로가 원을 그리지 않게 하고, 입력 중립 또는 30° 이상 방향 변경 시 새 카메라 기준을 사용한다. 수동 look 제스처는 해당 이동 구간에서 자동 정렬을 억제하며 방향 변경 시 해제한다. 1인칭·전투·등반·비행·수영·메뉴는 제외한다. [카메라 회귀](../../tests/camera-comfort.mjs): 실제 수정 코드의 격리 실행으로 30/60/120fps, 직진 유지, 수동 드래그 및 새 방향, 횡이동, 비활성·등반 PASS. 브라우저/실기기 체감 NOT RUN.
