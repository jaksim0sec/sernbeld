## 1. 최종 게임 비전과 이번 베타의 역할

최종 세른벨드 = 《아이리움 윙》에서 착안한 **직업 발견·히든 성장·거대한 세계 사건** + 《마비노기》식 **판타지 생활의 자율성** + 아름다운 3D 공간 + **사용자 제작 스킬**.

직업은 생산·채집 / 제작·가공 / 상업·유통 / 전투·모험의 **네 가지 활동 계통**이며, 고정 클래스나 독점적인 전직 목록이 아니다. 마법은 전투·모험에 포함되지만 제작·생활에 응용할 여지는 열어 둔다. 학문·예술·음악·탐험을 삭제한 게 아니라 독립 상위 직업군에서 내려 실제 콘텐츠와 직함으로 배치한 것이다.

**Beta 1의 증명 과제:** '플레이어가 하나의 작은 판타지 지역에서 생업을 선택하고, 독자적 기술을 개발하며, 세계의 사건에 여러 방식으로 관여할 수 있다.'

**비목표:** MMORPG 서버·다중 이용자 동기화, 전 세계 완성, 범용 AI NPC, 완전 자유 제작 엔진, 모든 무기/마법어, 전체 캐릭터 외형 커스터마이징, 경제 전수 시뮬레이션, 강제 메인 퀘스트.

## 2. Beta 1 완료 조건 (Definition of Done)

1. **플레이 공간:** 기존 지형을 활용한 카엘 항구 + 채집 가능한 외곽길 + 등대/유적 주변의 위험 지점. 별도의 대륙이나 스트리밍 엔진은 요구하지 않음.
2. **경로 네 가지:** 생산·채집, 제작·가공, 상업·유통, 전투·모험이 각각 **15분 이내에 의미 있는 성취 하나**를 낼 수 있어야 함. 특정 직업·길드 가입은 진행 조건이 아님.
3. **커스텀 스킬:** 최소 물리 1종(찌르기)과 마법 1종(발사/충격 계열)의 설계→유효성 검사→현장 시험→수정→저장→재실행 완성. 설정 차이가 실제 동작 시점, 궤적/범위, 피격, 에너지 사용에 반영됨.
4. **성장:** 선택한 활동의 숙련이 작업 품질, 효율, 허용 조합 중 최소 하나를 실제 변경. 단순 경험치 숫자만 증가하는 건 불합격.
5. **NPC:** 최소 3명의 기존 주민이 근무 장소에서 하루 한 번 **실제 생산/재고/요청 상태 변화**를 일으킴. NPC가 움직이는 연출만으로는 불합격.
6. **사건:** 하나의 선택형 지역 사건이 발생하고, 서로 다른 계통의 방법으로 참여 가능하며, 참여하지 않아도 NPC들에 의해 시간이 지나면서 부분 진행됨. 결과는 환경/거래/대화 중 둘 이상에 반영되고 저장됨.
7. **자유:** 인트로를 끝내거나 스킵한 뒤 어느 경로든 바로 선택 가능. 전투·빚·숙박비·길드·보스 처치는 강제되지 않음.
8. **호환:** 기존 `sernbeld.save.v1`, 고유 아이템, 웨이포인트, 장비, 채집 상태, NPC 상태를 보존. 모바일 입력, PWA 오프라인 시작, 온라인 새 버전 새로고침 검증.
9. **최종 플레이테스트:** 신규 저장 기준 **30~45분**의 콘텐츠를 한 지역에서 경험할 수 있고, 전투를 거부한 플레이어도 의미 있는 진행과 보상을 얻을 수 있음. Galaxy S22 등 대표 실기기에서 10분 플레이 무중단, 체감 끊김 없는 조작을 확인. FPS는 관측해 보고하고 베타 기준값은 실측 후 확정.

> 15분/30~45분은 콘텐츠 분량 목표치이지 개발 소요 기간 추정이 아니다. '모든 경로를 반드시 순서대로 클리어'하라는 뜻도 아니다.

## 3. 세로 슬라이스로 검증할 실제 플레이

| 계통 | 베타 행동 | 필요한 게임 오브젝트 | 성취·성장 | 다른 계통과 연결 |
|---|---|---|---|---|
| 생산·채집 | 들판 약초·꽃·수정 채집, 위치/희귀도 탐색 | 기존 `field_herb`, `wind_blossom`, `clear_crystal`, `Gatherables` | 채집 숙련으로 자원 판별 또는 채집 효율 향상 | 조제 재료, 등대 부품 공급, 시장 판매 |
| 제작·가공 | 약초 작업대에서 회복 연고, 공방에서 등대용 광원 부품 제작 | 약초 작업대 1, 대장간/공방 상호작용 1, 레시피 2 | 제작 품질과 실패/소모가 숙련에 따라 실제 변동 | 장터 판매, 위험 지역 준비, 사건 해결 |
| 상업·유통 | 시장과 항구의 서로 다른 수요·재고 확인, 물품 구매/판매/납품 | 상인 2명, 거래 패널, 재고·가격 상태 | 거래 숙련으로 가격 정보/수수료 개선 | 부족한 물자 보급, NPC 생산물 순환 |
| 전투·모험 | 물리·마법 사용자 스킬로 훈련 표적 시험, 등대 외곽의 적대 자동인형 1종과 선택적 대치 | 훈련 표적 1, 적대형 오브젝트/적 1종, 에너지/충돌 | 기술 숙련으로 조합 허용치·효율 개선 | 현장 단서 발견, 희귀 재료, 사건 선택지 |

**베타용 대표 레시피 (콘텐츠 초안):** `field_herb ×2 + wind_blossom ×1 → healing_balm ×1`(회복 소비품), `clear_crystal ×1 + river_pebble ×2 → beacon_core ×1`(등대 사건용 작업물). 재료는 기존 게임 데이터에 실제 존재하며 새 생산품 ID만 추가한다. 요구량·가치·회복량은 초기 밸런스 후보이며, 테스트 이후 조정할 수 있다.

**기본 접근:** 시작 소지금이 부족하더라도 무료 채집과 기본 전투/마법 학습은 가능. 제작은 재료로, 거래는 소액 기본 소지금 또는 현장 물품 납품으로 시작할 수 있게 설계. 모든 경로가 같은 보상으로 합쳐질 필요는 없음.

## 4. 스킬 커스터마이징: 베타 기능 계약

### 4.1 공통 스킬 모델

`Save.data.customSkills` (없으면 `[]`), `Save.data.mastery` (없으면 `{}`), `Save.data.vitals` (없으면 베타 기본값으로 보정). 기존 저장 `v:1` 유지. 스킬 항목에는 `id`, `name`, `discipline`, `config`, `version`을 저장하고 런타임 애니메이션/메시/투사체는 저장하지 않는다.

**런타임 계약:** 설정 검사(`validate`) → 실행 스텝 배열 생성(`compile`) → 자원/상태 검사(`canCast`) → 실제 프레임 동작·충돌 실행(`execute`) → 성공 시 저장/이벤트 통지. 한 스킬의 자원은 한 번만 차감하고, 실패하면 차감하지 않는다. 발동 중 재로드·지역 해제·장비 변경이 생겨도 중복 보상이 없어야 한다.

핵심 설정 필드 제안: `baseAction`, `repeat`, `speed`, `power`, `energyDistribution`, `manaInjection`, `direction`. 공통 문법은 데이터 규칙만 공유하고 UI를 강제 통일하지 않는다.

### 4.2 물리: 찌르기 → 사용자 연속기

베타는 기본 동작 `thrust` 하나를 재조합한다. 시험 가능한 값은 **횟수 1~3**, **속도 0.75·1.0·1.25**, **위력 0.75·1.0·1.25**, **마력 주입 없음/균등/마지막 타격 집중**. 각 반복은 별도 시간에 실행돼야 하며 **정면 타격 거리/충돌, 손·무기 동작 및 실제 경직 시간**이 바뀐다. 마력은 일괄 공격력 보너스가 아니라 선택한 타격의 밀침/잔류 효과 등을 바꿔야 함.

스태미나 요구량 예시: `ceil(8 × repeat × power × speed²)`; 마력 요구량은 각 타격의 주입량 합계. 자원·숙련이 부족한 구성은 실행 전 조정 안내. 수치 공식은 베타 밸런스 초안이며 구현 전에 테스트 케이스로 고정한다.

### 4.3 마법: 원형 마법진은 **마법 전용**

홀로그램 마법진의 **빈 슬롯에 마법어를 삽입**하고, 배치한 마법어를 눌러 속도·반복·위력·마력 주입량을 팝업에서 조정. 마법어 1차 최소 집합은 `발사` + `충격`처럼 실제 물리 동작이 구분되는 2개로 시작. 마법에는 실제 생성·이동하는 투사체/효과, 충돌, 범위/넉백, 발동 타이밍이 있어야 함.

최대 마력은 **사용 가능한 슬롯 수**를, 현재 마력은 **실제 실행 가능 여부**를 결정. 둘은 별개. 최초 구현 후보는 최대 마력 30/70/110일 때 사용 슬롯 2/3/4(상한 4)로 잡되, 수치 자체는 사용성 검증 후 확정. **다른 기술/제작 인터페이스를 원형 마법진으로 통일하지 않는다.**

### 4.4 숙련과 제한

- 물리 제어 숙련 0~3, 마력 제어 숙련 0~3을 베타 내부 등급으로 가정. 높은 반복·속도·복잡한 마법어 결합을 해제.
- 단순한 버튼 반복 대신 최초 성공, 다른 대상·거리에서의 안정적인 사용, 기술 훈련·스승 상호작용에 숙련 보너스.
- 기본 스킬은 설계 UI 없이 바로 사용 가능. 저장한 커스텀 기술을 단축 슬롯에서 교체/재사용.
- 테스트에서는 **다른 설정 2개가 서로 다른 애니메이션 시간/투사체 이동/타격 순간/자원값을 낳는지** 실측.

## 5. 베타 지역 사건: '카엘 등대의 빛' (임시 서사, 미확정 세계관)

기존 월드의 등대·항구·시장·대장간을 활용하므로 최소 제작으로 네 계통을 연결할 수 있다.

**시작:** 게임 내 2일째, 등대의 광원이 불안정해져 야간 입항이 줄고 상인 재고가 부족해진다. 사건은 게시판이나 NPC 대화로 알 수 있지만 수락하지 않아도 발생한다.

**해결 경로:**
- 생산: 인근에서 수정 확보 후 조합/상인에게 납품
- 제작: 등대용 부품 `beacon_core` 제작 후 제공
- 유통: 남은 부품·자재를 시장과 항구 사이에서 운송·거래해 부족 해소
- 전투/모험: 등대 주변 유적의 이상을 조사하고 선택적으로 파수체와 대치해 원인 단서 발견

**월드 반응:** 등대 광원이 꺼짐→불안정→복구 상태로 바뀌고, 적어도 **상인 재고/가격 1개, NPC 대사 2개, 야간 등대 광원**에 반영. 아무것도 하지 않을 경우 3일 후 주민들이 부분 복구하며 정상보다 낮은 보급 상태가 남을 수 있다. 스토리 장치가 모든 플레이어를 주인공으로 강제하지 않음.

**저장:** `Save.data.incidents.kael_beacon`에 `phase`, `contributions`, `resolvedBy`, `lastProcessedDay` 등을 저장. 게임을 종료했다 다시 켜도 보상 중복·사건 역주행이 없어야 함. 서버 없는 오프라인 버전은 **게임 내 날짜/활동 기준 결정론적 업데이트**만 사용.

**비밀 발견 1개:** 등대 관련 오래된 기록을 찾아 특수 마법어 또는 물리 기법의 단서를 얻는 선택형 발견. 강제 보스전/길드 가입 없이 획득 가능하도록 대체 경로 마련. 해당 직업/콘텐츠는 베타에서 완성된 거대 히든 클래스가 아니라 **발견형 성장의 짧은 시연**임.

- 기존 `fresh()`, `Save.load/write/reset`, `WorldRegions`, `GameEvents`, `Inventory` 경로 확인. 기존 세이브 샘플 백업 후 모든 베타 데이터는 **선택적 새 필드**로 추가. 캐릭터 외형 담당 파일 수정 금지.
- 현재 인트로에 '빚', '조합 이름부터 올리기'가 있고 `Society.goal()`이 길드 등록을 기본 목표로 표시한다. **강제 경로처럼 읽히는 표현 제거 또는 선택형 추천으로 변경**. 기존 길드 기능 삭제 금지.
- **승인 게이트:** 신규/기존 저장 모두 실행, 자유 탐험·채집·지도·장비·기존 의뢰·재접속 정상. 의도적으로 늘린 UI/씬 오브젝트 때문에 테스트가 실패하지 않으면서 기존 핵심 기능은 계속 검증됨.

### P1a. 조립형 스킬 계산/저장만 완성 (게임 밖 단위 테스트까지)

- **신규 파일 후보:** `src/core/skill-engine.js` (스킬 schema 유효성, 자원·숙련 제한, 실행 타임라인 생성), `tests/skill-engine.mjs`.
- **수정 후보:** `src/gameplay/gameplay.part.js` (`Save` 기본값, 스킬 저장·이벤트 연동), `sw.js` (새 모듈 사전 캐시), 필요 시 `tools/build-game.mjs`.
- **행동 테스트:** 횟수·속도 변화에 따라 타격 스텝 수/시간/소모량이 달라짐, 마력 부족 실행 실패, 위조된 설정 거부, 이전 저장과 새 저장 정상, 재로드 후 설계 정보 동일. 실행 실패 시 자원 0 차감.
- **승인 게이트:** 브라우저 콘솔 없이도 2개 이상의 스킬 설정을 저장/재로드하며 결과를 재현할 수 있음.

### P1b. 실제 물리·마법 실행 + 모바일 설계 UI

- **수정 후보:** `src/gameplay/gameplay.part.js`의 `Combat`, `ViewModel`, `boot` 입력 연결, `index.html`, `styles/menus-and-overlays.css`, `styles/responsive.css`, `tests/webgl-smoke.mjs`, `tests/mobile-regression.mjs`.
- 기존 `Combat.attack`, `Combat.update`, `maktwoAttackPose`, `maktwoWorldRay`을 재사용하되 **찌르기 전용 동작/충돌**을 구현. 연속 조합은 지연 시간에 실제 타격 여러 번으로 실행. 단일 숫자 데미지 배수로 위장하지 않음.
- 마법진 별도 패널: 원형 슬롯 → 마법어 선택 → 해당 슬롯 클릭 설정 팝업 → 테스트/저장/단축 슬롯. 투사체 충돌은 월드/대상에 맞아야 함.
- **승인 게이트:** 속도가 다른 물리 조합 2종과 마법 설정 2종이 화면에서 다르게 동작. 모바일 탭/드래그·닫기·재입력·PWA 재시작에도 설정 유실 없음.

### P2. 네 직업군의 최소 완결 플레이

- **신규 파일 후보:** `src/core/recipes.js`, `src/core/market-state.js`, `tests/crafting-trading.mjs`.
- **수정 후보:** `src/gameplay/gameplay.part.js`의 `GATHER`, `ITEMS`, `Explore`, `Society`, `GameUI`, 기존 상점 대사; `index.html`/관련 CSS.
- 기존 채집 품목을 레시피와 납품으로 연결. 제작 시 재료/수량 검증→일괄 차감→결과 지급→한 번 저장→결과 이벤트. 상인 2명에게 독립된 재고/매입·매출 제공, 같은 장소 즉시 무한 차익 불가.

- **승인 게이트:** 아무 퀘스트도 수락하지 않은 신규 플레이어가 재료 채집→제작→사용/판매, 소액 거래→다른 상인 납품, 물리·마법 훈련 중 하나를 각각 완료 가능. UI에 재료 부족/재고 부족/가격 표시.

### P3. NPC의 '일'과 세계 상태를 실제 변화에 연결

- **신규 파일 후보:** `src/core/settlement-sim.js`, `tests/settlement-sim.mjs`.
- **수정 후보:** `src/gameplay/gameplay.part.js`의 `Townsfolk`, `Society`, `GameClock`, `WorldRegions` 연결.
- 기존 주민 중 장인/시장 상인/여관이나 항구 근로자 등 **3명부터** 하루 단위 생산·재고·수요 변화에 연결. 3D 아바타 이동은 기존 일과를 재사용하고 데이터 상태는 날짜 변경 때만 갱신. 지역이 비활성이라도 날짜 기반 누락일을 중복 없이 한 번에 처리할 수 있어야 함.
- **승인 게이트:** 플레이어가 가만히 있거나 쉬어도 다음 날 상인 재고·NPC 대화·작업 결과가 달라짐. 세이브로드 후 같은 날짜를 두 번 처리하지 않음.

### P4. 선택형 지역 사건과 발견 콘텐츠

- **신규 파일 후보:** `src/core/incident-state.js`, `tests/kael-beacon-incident.mjs`.
- **수정 후보:** `src/gameplay/gameplay.part.js` 지역 상호작용·대화·월드/등대 광원·이벤트 구독·적대형 파수체/훈련 표적, `src/world/region.part.js` 지역 사건 데이터, 해당 UI.
- P2의 재료/제작/거래, P1의 전투 기술을 **하나의 사건**에 연결. 단서 하나는 탐험만으로 얻도록 설계. 기존에 제거한 양·들개 야생동물 콘텐츠와 오래된 의뢰를 복원하지 않음.
- **승인 게이트:** 플레이 방식 2개 이상으로 완료/부분 완료 가능, 플레이어 미참여 시 NPC에 의한 부분 진전, 등대의 가시적 상태 변화, 보상/저장 중복 없음.

### P5. 콘텐츠 연출과 베타 출고

- **작업:** 접근성이 나쁜 경로/상호작용 거리/오브젝트 가시성 개선, 튜토리얼 팝업 대신 자연스러운 발견 유도, 훈련 표적과 약초 작업대·상점 간판을 한눈에 인지할 수 있는 비주얼, 모바일 성능 손실 최적화.
- 캐릭터 얼굴 커스터마이징·새 렌더러 재작성·전면 UI 교체·전체 경제 엔진 확장은 **이번 베타 게이트 아님**.
- **승인 게이트:** 실제 플레이어 동선 검수, 신규/기존 저장, 터치 입력, 오프라인/업데이트 테스트, 기존 주력 브랜치와 회귀, 아래 전체 검증 통과.

## 7. 작업 의존성 및 차단 관계

```
기존 PWA·월드·세이브·엔티티·이벤트·인벤토리 (이미 존재)
                    │
                 P0 저장 계약
                 /       \
        P1a 스킬 계산     P2 제작/교역 규칙
              │                  │
        P1b 스킬 실전        P3 NPC 직업 생산
              \                  /
                 P4 지역 사건
                      │
                 P5 베타 검수
```

**원칙:** P1a와 P2의 순수 데이터 규칙은 독립적으로 작업할 수 있어도, 게임 번들·저장 포맷·UI를 만지는 통합은 순차 진행한다. 코드가 큰 `gameplay.part.js`를 복수 에이전트가 동시에 수정하지 않는다. 매 단계는 `game.js` 재생성과 캐시 버전 갱신을 포함해 독립적으로 실행 가능해야 한다.

## 10. 첫 구현 담당자용 세부 계약 (B1-01, B1-02)

이 절은 P1의 **실제 첫 두 작업을 바로 착수할 수 있게 하는 설계 계약**이다. 뒤 단계의 내용은 이 작업 결과를 확인하고 상세화한다.

### B1-01: 계산 가능한 스킬 구성

- `src/core/skill-engine.js`에서 최소 다음 순수 함수와 반환 형태를 공개한다.

```js
validateSkill(config, actor)
// => { ok: boolean, errors: string[], cost: { stamina: number, mana: number } }

compileSkill(config, actor)
// => { duration: number, steps: [{ at: number, action: string, power: number, mana: number }], cost: { stamina: number, mana: number } }
// 잘못된 구성이라면 명확한 오류를 던지거나 실패 결과를 반환. 자원 차감/DOM/WebGL 변경은 이 함수에서 하지 않음.
```

- `config` 물리 최소형: `{ discipline:'physical', baseAction:'thrust', repeat:1, speed:1, power:1, manaInjection:0, energyDistribution:'even' }`.
- `actor` 최소형: `{ stamina:30, mana:20, maxMana:30, physicalControl:0, magicControl:0 }`.
- 베타 1차 비용 공식은 `stamina = ceil(8 * repeat * power * speed**2)` 및 `mana = 총 주입량`으로 **정확히 고정하고 테스트**. 마력 미사용 기본 찌르기는 `{stamina:8,mana:0}`을 반환.
- 반영 가능한 물리 조합: `physicalControl:0`은 반복 1회·속도 1.0 이하, `physicalControl:1`은 반복 최대 2회·속도 최대 1.25, `physicalControl:2+`는 반복 3회. 실제 밸런스는 플레이테스트에서 변경하되 검증 가능한 현행 공식 없이 개발하지 않는다.
- 최소 테스트 이름/결과: `base_thrust_cost_is_8`, `two_thrusts_have_two_timed_steps`, `higher_speed_shortens_duration_and_raises_cost`, `insufficient_stamina_is_rejected_without_mutation`, `untrained_three_hit_combo_is_rejected`, `unknown_block_is_rejected`, `skill_json_roundtrip_preserves_config`.
- `src/gameplay/gameplay.part.js`에 새 ES 모듈을 정적으로 연결한 다음 `node tools/build-game.mjs`로 `game.js` 재생성. 독립 `src/core/` 모듈은 기존 `*.part.js` 연결 파트와 다르므로 **소스 조각 자체를 독립 import 대상으로 오인하지 않는다.**

### B1-02: 실제 충돌과 동작에 연결

- 기존 `Combat.attack/update`, `maktwoAttackPose`, `maktwoWorldRay`의 정상 기본 공격을 유지한다. 커스텀 찌르기만 별도의 물리 동작으로 실행하도록 최소 범위 확장.
- `compileSkill`의 `steps` 중 `action:'thrust'`가 두 개면 서로 다른 프레임/시점에 타격 판정이 **정확히 두 번** 발생해야 한다. 설정의 `speed`가 바뀌면 이 시점과 선행 동작 시간이 함께 변한다.
- 훈련 표적을 하나 두고 타격 횟수·접촉 결과를 개발 훅 또는 테스트 로거로 관측한다. 단순히 HP에 `repeat × damage`를 한 번 더하지 않는다.
- 매 타격 시 월드 충돌 및 타격 대상 판정을 분리하되, 현재 NPC/월드 전체에 임의 데미지를 주도록 확장하지 않는다.
- 주요 테스트: `single_hit_produces_one_contact`, `combo_produces_two_separate_contacts`, `blocked_by_wall_no_target_hit`, `cancel_does_not_duplicate_resource_spend`, `legacy_attack_still_works`.
- B1-02의 실제 WebGL 검증이 끝나야 B1-03 물리 편집 UI로 넘어간다. **예쁜 편집 UI를 먼저 만들지 않는다.**
