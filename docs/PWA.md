# 세른벨드 오프라인 PWA

## 범위
- `index.html`에서 설치 매니페스트 및 `pwa.js`를 로드한다.
- `sw.js`가 게임 실행에 필요한 HTML/JS/CSS, SVG, GLB 및 Character Studio와 기본 의상 데이터를 **전부 받아야 설치에 성공**한다.
- Google Fonts는 외부 리소스라 오프라인에서 시스템 대체 폰트를 사용한다.
- `file://`에서는 동작하지 않는다. HTTPS(GitHub Pages 포함) 또는 `localhost`에서 접속해야 한다.
- 설치 후 첫 온라인 방문을 완료해야 오프라인 실행할 수 있다. 최초 캐시 저장 전에 탭을 닫지 않는 것이 좋다.

## 새 버전 우선 정책
1. 모든 동일 출처 GET 요청에서 Service Worker는 **네트워크 우선**으로 `fetch(request, {cache:'no-store'})`를 호출한다.
2. 성공 응답을 최신 런타임 캐시에 저장한다. 네트워크 오류 때만 기존 런타임/오프라인 설치 캐시를 사용한다.
3. 실제 404/500 응답은 이전 캐시로 덮어 숨기지 않는다.
4. 새 Service Worker가 대기 중이라면 하단에 **업데이트** 버튼을 보여준다. 게임 중 강제 새로고침은 하지 않는다.
5. Service Worker 코드가 그대로여도 새로운 `index.html`, `game.js`, CSS, SVG 파일을 감지할 수 있게 HEAD 응답의 ETag 또는 Last-Modified/Content-Length를 비교한다. 새 빌드가 발견되면 이용자가 **업데이트**를 눌러 직접 새로고침한다.
6. PWA 셸 캐시의 이름을 새 버전으로 바꾸면 이전 셸과 런타임 캐시는 activate 후 삭제된다. 서버 에셋 변경 시에는 같은 SW 버전이어도 새 파일을 네트워크에서 가져온다.
7. Scope, start_url, SW cache 경로는 전부 상대 경로이므로 GitHub Pages 저장소 하위 디렉터리에도 대응한다.

## 권장 배포 규칙
- 게임 콘텐츠를 변경했을 때 `sw.js`의 `VERSION`을 함께 올리면 새 에셋을 원자적으로 다시 설치하고 업데이트 버튼을 보여줄 수 있다.
- SW 코드를 업데이트하지 않고 배포하더라도 온라인 네트워크 우선 + 파일 메타데이터 검사 때문에 **리로드 시** 최신 에셋을 가져온다.
- 미리보기에서 구버전이 나타나는 경우에도 웹 서버/배포 CDN 자체의 응답이 최신인지 먼저 확인해야 한다. SW만으로 원격 CDN의 잘못된 응답까지 고칠 수는 없다.
- 오프라인에서 사용자가 입력한 플레이 진행 상황을 서버와 동기화하는 기능은 별도 작업이다.

## 검증
CI에서 `node tests/pwa-offline.mjs`를 실행한다.
1. Chromium에서 정상 게임 WebGL 실행
2. 오프라인 셸의 필수 에셋 캐시 저장 검증
3. 이미 캐시된 파일을 서버에서 변경하여 온라인에서 최신 버전 조회 확인
4. 네트워크를 끊고 새로고침하여 게임 WebGL 및 리소스 로드
5. 오프라인에서 최근에 저장된 파일을 이용하는지 검증
6. 다시 온라인에서 해당 파일을 삭제한 뒤 404를 반환하는지 검증

유의: 자동화는 Chromium 환경에서 확인한다. 실제 모바일 기기에 설치하는 과정 자체는 별도로 실기기 검증해야 한다.

## 셔츠 분할 데이터 복구

`runtime.json`은 각 Base64 분할 파일의 정확한 Git blob SHA-1(바이트 무결성 식별용)을 기록한다. 로더는 버전 쿼리로 파일을 요청하고 해시와 기존 형상 검사를 모두 통과해야 사용한다. 실패하면 메타데이터부터 모든 분할 파일을 새 복구 URL로 한 번 재요청한다. SW 42는 복구 요청에 캐시 대체를 사용하지 않으며, 정상 오프라인 요청의 셸 대체는 로더에서 다시 검증된다. 지속 실패는 체형·파일 진단을 반환한다. 저장 데이터 및 기존 형상은 변경하지 않는다. `node tests/shirt-recovery.mjs`로 손상·구버전 메타·실제 데이터·SW 경로를 검사한다.
