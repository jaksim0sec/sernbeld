## T1 중앙 키워드 기획 및 생산 명세 확정

- 최신 main의 실제 NPC ID·직업·지역·생활상·아이템·사건·서비스 및 대화 계약을 확인한다. 중앙 에이전트는 대사 대신 화제 키워드, 성격/말투, 사용자 답변 분기 방향, 조건, 실제 참조 ID 및 생산 수량을 계획한다.
- named/personal/event 및 2~4인 담화를 중복 없는 배치로 나누고 안정적인 ID 범위와 허용 참조 목록을 지정한다. 미구현 사건·효과·설정은 생산 대상에서 분리한다. 현재 생산 범위와 수량은 T1에서 실제 콘텐츠에 맞게 정한다.
- 외부 에이전트는 프로젝트 기억도 저장소 접근도 없는 독립 세션으로 가정한다. 각 배치에 자체 완결형 브리핑을 반드시 제공한다. 단순 키워드와 규격 링크만 전달하지 않는다.
  - 게임 소개: 세른벨드는 아름다운 애니풍 판타지 세계에서 정해진 주인공·직업·운명 없이 무명인부터 자기 삶을 개척하는 모바일 웹 오픈월드 RPG다. 카엘 항구는 노동·생활·교역의 실제 공간이며 NPC는 플레이어만을 위해 존재하거나 모든 말을 의뢰로 연결하는 존재가 아니다. 전투·길드·메인 퀘스트는 필수가 아니다. 미확정 출신과 고대 문명 등 예시 설정을 정설로 쓰지 않는다.
  - 이번 작업 목적: 이미 구현된 선택지 기반 대화 엔진에 실제 콘텐츠를 채우는 작업이다. 자유 입력 AI 대화, 엔진 개발, 신규 세계관 확정이나 직접 게임 등록은 외부 생산 범위가 아니다. 고유 NPC 대화, 직업/지역별 범용 대화, 실제 상태 기반 사건 화제, 조건이 맞을 때의 2~4인 주민 담화와 사용자의 후속 응답 분기를 작성한다.
  - 현황·자료: 최신 main에서 확인한 카엘 지도/장소 설명, 실제 인물 이름·ID·직업·일과·기존 발화 및 확정된 배경, 아이템·의뢰·서비스·사건과 사실 키의 허용 목록을 발췌한다. 구현됨/기획됨/미확정을 구분하고 없는 데이터는 지어내지 않는다. 배치별 필요한 자료만 제공하되 전체 게임 소개와 이번 목적은 모든 배치에서 반복한다.
  - 제작 방법: 정확한 현행 JSON 스키마와 실제 유효한 named/personal/event 및 그룹 예시(배치 해당 유형), 분기·종료·조건·허용 효과·지식 소유 규칙, 배정 키워드/ID/수량, 금지 사항과 반환 파일 형식을 본문 또는 동봉 파일로 전달한다. 외부 에이전트가 GitHub 링크 열람 없이도 작성할 수 있어야 한다.
  - 전달물: 각 세션에 그대로 첨부할 자체 완결형 프롬프트 + 필요한 참조 데이터 파일을 만들고, 자료가 크면 ZIP으로 묶는다. 출처 SHA와 배치 ID를 명시하며 다른 배치나 이전 대화 내용을 읽어야 한다는 전제를 두지 않는다.
- docs/content/kael-dialogue/에 키워드/배치 명세(JSON)와 각 외부 세션에 전달할 생산 프롬프트를 저장한다. 대화 계약의 정확한 JSON 예시 및 조건·효과·그룹·종료 규격을 포함하거나 함께 전달한다. 중앙 에이전트는 이 단계에서 실제 대사를 생산하거나 게임에 등록하지 않는다.
- 완료 기준: 실제 참조가 확인된 생산 명세, 배치별 키워드·ID·목표 수량 및 저장소나 이전 세션을 모르는 에이전트도 독립 생산 가능한 자체 완결형 외부 세션용 프롬프트 및 참조 자료 확보. 다음 주소 T2.

## T2 외부 세션 대화 생산 및 수신

- T1 자체 완결형 생산 패키지를 사용자에게 배치별로 제공하고, **다른 세션에서 대화 템플릿을 생성하도록 요청**한다. 에이전트는 배정된 배치만 독립 생산하고 저장소·게임 코드에는 손대지 않는다.
- 중앙 세션은 외부 세션 실행을 가장하지 않는다. 사용자가 돌려주는 JSON/ZIP/파일을 받으면 출처, 배치 ID, 실제 개수, 명세 대응 및 누락을 기록한다. 이미 제공된 파일은 재요청하지 않는다. 미수신 배치가 있다면 명시하고 해당 범위의 생산 완료로 간주하지 않는다.
- 필요 시 규격 불일치/누락된 배치에 대해 재생산 프롬프트를 제공한다. 원본과 수정본을 구분한다.
- 완료 기준: 합의된 배치의 실제 생산물 및 출처·수량·누락 목록 확보. 원본 수신 전 T3 진행 금지. 다음 주소 T3.

## T3 병합·규격 검증·키워드 재정의·자연성 검수

- 수신 원본은 보존하고 staging에 병합한다. ID/의미 중복, topicId 충돌, node/slot/choice 참조, 실제 NPC/직업/지역/태그/사건 fact 및 effect/service 참조를 최신 main과 대조한다.
- 현행 graph validator/registry를 기존 콘텐츠와 함께 실행하고 자동 순환, 무조건 종료 경로, 조건, ok/fail/stale, 지식 소유, 그룹 참여, 고유/범용/사건 우선순위와 기존 서비스 보존을 검증한다. 미구현/미승인 기능 의존 템플릿은 보류한다.
- 중앙 에이전트가 실제 카엘 콘텐츠에 따라 키워드와 분류를 재정의하고 최종 template/topic ID와 별도 매핑한다. 계약에 없는 필드를 그래프에 추가하지 않는다.
- 모든 대화 경로에서 사용자 답변과 NPC 반응의 인과·맥락, 말투, 반복, 실제 사건/친화도/지식 조건, 자연스러운 종료와 화제 복귀를 검수한다. 무관한 응답, 전원 의뢰화, 설정 날조, 구현되지 않은 행동 약속은 수정하거나 보류한다. 수정 뒤 규격 검사를 다시 실행한다.
- 완료 기준: 최종 통합 후보 및 키워드 매핑, 전체 검수 결과와 통과/수정/보류 수량·이유, 대표 분기 경로 및 실제 검사 근거. 다음 주소 T4.

### T3 콘텐츠 품질 평가 기준 (A/B/C 검토에서 보강)

규격 검증과 문학적·게임 경험 품질을 독립적으로 판정한다. JSON이 유효하거나 수량이 충족돼도 콘텐츠 품질 PASS가 되는 것은 아니다. 아래 기준은 named/personal/event/group의 목적에 맞춰 적용하며, 범용 폴백에 고유 NPC 서사나 사건 효과를 강제하지 않는다.

- 중복/유사도 및 길이 자동 검사는 보조 수단이다. 정상적인 공용 종료 문구는 허용하고 의미 중복·직업별 말투 획일화·반복 대화 구조는 별도 검토한다. 모든 유효 경로의 의미 검수 후 통과/수정/보류를 그래프 단위로 판정하고, 수정분만 재검수·규격 재검증한다. 짧은 대화를 일괄 장문화하거나 기계적으로 깊이 2~3을 강제하지 않는다.
- 이전 평가 참고: A(공통/주민, 5.5/10)는 짧은 폴백으로 활용 가능하나 첫 화제의 구체적 전개 부족; B(상인/부두 일꾼, 7.5/10)는 분기 및 내용 다양성의 참고 사례이나 설명·교훈형/획일적 말투 개선 필요; C(어린이/경비, 4.5/10)는 역할별 개성과 응답 의미·분기 보강 우선. A/C는 각각 24개 그래프(120노드, 72 NPC 페이지, 깊이 1, 정상 경로 48), B는 제공된 생성 코드 기준 24개 그래프·깊이 최대 3이며 세부 수치는 실제 JSON 수신 후 재집계한다. 이 점수는 콘텐츠 사전 평가이며 현행 validator나 런타임 검증·등록 승인 결과가 아니다.
- 수신 A/B/C의 범용 ID/주제 구성은 저장소 T1 manifest의 A/B 명세(고유·범용·그룹 및 4개 공유 topicId)와 다르다. T2에서 최신 합의된 배치 범위·ID/주제 매핑·미수신 named/group 데이터를 확인하고 차이를 기록한다. 다른 생산 명세의 파일을 기존 A/B 완료로 간주하거나 검수 없이 topicId를 새로 늘리지 않는다. 실제 합의 범위가 변경되었다면 명세를 먼저 정합화하고 T3에서 화제 폭증·resolver 우선순위와 변형 선택을 검증한다.

## T4 실제 콘텐츠 등록 및 최종 통합

- 최신 main 및 활성 작업 점유를 다시 확인한다. 기존 production 진입점과 계약에 맞춰 검수 완료 데이터만 등록하고 기존 선형 담화, 일반 서비스, 저장 상태를 유지한다. 병렬 작업과 겹치는 game.js/sw.js/runtime 등의 변경이 필요한 경우 점유 해제·범위 조정 후 작업하며 임의로 덮어쓰지 않는다.
- 실제 등록 배치에 대해 registry/resolver 및 대화·그룹·생활 세계 관련 회귀를 실행한다. 대표 named/personal/event 및 사용자 분기(종료/서비스/실패 포함)를 실제 게임에서 검증 가능한 범위까지 확인하고 필요한 번들/PWA·인프라 검사 및 최종 CI를 수행한다. 테스트 미실행을 PASS로 표시하지 않으며, 필수 실게임/실기기 검증은 같은 작업의 최종 게이트로 유지한다. 단순 CI 대기로 독립 작업을 막지 않는다.
