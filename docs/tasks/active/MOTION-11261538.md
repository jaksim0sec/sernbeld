## 접근 결정 및 공용 계약 (제안)

- 대안 A: 기존 Player/Townsfolk 내부만 계속 패치. 변경 비용은 작지만 충돌 프로파일·전환·판정 규격의 중복을 해결하기 어렵다.
- 대안 B(권고): 기존 질의·solver를 기준으로 매개변수화 및 공용 데이터 계약을 단계적으로 적용. 기존 플레이와 절차적 모션을 보존하고 증분 검증 가능.
- 대안 C: 물리엔진·모션 그래프 전면 교체. 현재 웹 성능/번들/카엘 지형/리그 회귀 위험과 근거 부족으로 범위 제외. B는 작성자 제안이며 엔진/저장/리그 비호환 변경은 별도 사용자 합의.
- 좌표: m, Y-up, 발 기준 물리 root, 안정 ID, 월드 좌표의 표면 접점/normal, 시간은 초, 각도는 계약상 rad. 시각 메시·물리 경계·게임 상호작용용 볼륨은 다른 목적의 표현; 메시 AABB를 무조건 충돌체로 쓰지 않는다.
- 제안 인터페이스(기존 함수에 어댑터 또는 작은 공용 모듈로 구현; 최종 이름은 T1에서 실측/확정): ActorBoundary {id,root, radius,height,eyeHeight,stepHeight,scale,layer,mask}; SurfaceContact {surfaceId,point,normal,kind,flags}; QueryContext {actorId,profile,previousRoot,nearby}; MotionState {action,phase,grounded,velocity,heading,contacts,transition,teleportId}. kind=terrain/solid/oneWay/water/dynamic; flags=support/block/climb 등 독립 정책. stable ID 및 정책은 메타데이터로 유지. 모든 값은 유한·유효 단위 검증.
- 경계 규칙: 정적/동적 broadphase 분리 또는 기존 해시 재사용, 근방 활성 액터만 좁은 판정; 렌더/LOD/모델 미로딩 여부 자체는 물리 활성의 기준이 아님. 먼 주민 논리 이동 유지, 활성 경계에서 안전한 스냅샷 인계. 플레이어/NPC/더미 동일 계약, 서로 지지면/등반면 기본 제외. 두 액터의 반경·높이를 각각 사용, 겹침 해소 순서 고정, 벽으로 밀어 넣지 않음. 일반 충돌·대화 접근·장식·일방향 지지·등반 정책 독립. 정적 월드/지역 활성·해제 규칙 보존.
- 물리 권위: fixed tick의 root/velocity/행동 상태만 권위; renderPos는 보간, 리그 root/IK는 제한된 표시 보정, 카메라가 물리에 쓰는 값은 입력/의도뿐. 이동·시각·카메라 단계에서 동일 높이 보정 중복 적용 금지. 순간이동/지역 전환/외형 재생성은 명시 reset. 물리 접촉을 못 찾으면 손발이 허공에 고정되거나 리그가 무한 늘어나지 않아야 함.
- 동세: 행동 목적, 무게중심 이동, 지지발, 방향성, 준비-본동작-회복, 몸통/골반/사지의 시간차, 궤적과 실루엣, 연속 전환을 기준. 과장 강도·타이밍은 실험으로 정하고 물리 좌표를 애니메이션으로 직접 변경하지 않음. 추후 NPC/비인간의 rig adapter는 기존 studio-v1 계약과 분리.
- 최적화: 동일 기기/해상도/그래픽/인구/시나리오 비교, p50/p95 CPU tick·frame ms, 활성 콜라이더/후보 쌍, pose/IK 비용·할당·메모리, LOD 및 50 주민. T1에서 기준 캡처; 60Hz tick budget 16.67ms는 전체 주기 상한(물리 자체 예산 아님). 제안 상대 게이트: 동일 부하 p95 프레임·물리 비용 기준 대비 10% 초과 악화 시 원인/개선 또는 사용자 승인; 성능 목표 충족 여부는 실제 S22급 결과와 구분. per-frame 전체 삼각형/N² 주민 판정 금지.
- 실험 규격: 기존 dev lab 재사용. 고정 seed/input timeline, actor/profile, fixture ID 및 표면/충돌 오버레이, tick/pose/phase/접촉/보정/비용 로그, 정면·측면·45°/실제 3인칭 캡처, 동일 조건 전후 비교, 한 번에 한 변수. 디버그 도구 기본 비활성. 저장·인벤토리·카엘/NPC 스케줄 오염 금지. 실제 게임과 별도 solver/Combat 복제 금지.

## 단계 실행 규칙

T1→T2→T3→T4→T5→T6(연속성 통과 후 카메라)→T7→T8. 8T는 XL에서 경계/실험/각 행동군/카메라/엔티티/생산 계약의 실패 원인과 선행 계약이 다르기 때문에 분리했다. 조사나 CI만을 위한 T는 없다. 각 T는 실패 재현/회귀 추가 → 최소 변경 → 직접 검증 → 기록/커밋을 같은 단계에서 수행. 기존 함수·테스트를 우선 확장하고 신규 경로는 해당 T 착수 시 확정. 아래 수치 중 기존값 외의 허용치는 제안이며 T1에서 baseline/rig 측정 후 근거와 승인 범위를 확정(무조건 느슨하게 변경 금지). 재현 가능한 입력과 결과를 trace로 기록한다.
