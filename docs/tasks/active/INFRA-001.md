- 기준은 `main`의 `2d3d488c`이다. 기존 게임과 아트 방향, 인체, 저장 데이터와 콘텐츠 계약을 보존한다.
- [AGENTS](../../../AGENTS.md) → 분야 지침·현재 소스 → 공용 제작 화면·검증 → 작업 상태·선례 갱신을 같은 저장소에서 실행한다.

- 배포는 검증한 커밋에 묶는다. 저장소 Pages 게시 소스가 GitHub Actions인지 원격에서 확인해야 한다.

## 구현 결정

- 기존 게임의 등록 포맷과 장비 기본값을 유지한다. 검증용 의상 두 개는 작업 화면에서 모듈을 직접 지정할 때 등록한다.
- 자동으로 생성물만 별도 커밋하던 경로를 같은 커밋에서 검증하는 방식으로 바꾼다. Pages에는 검증에 실제로 사용한 트리를 전달한다.
- 기존 비교 테스트 중 구조 분리 전후의 DOM과 CSS 동일성을 가정하는 경우는 역사적 비교로 남기고, 현재 트리에서 판단 가능한 조작과 호환성을 main에서 실행한다.

## 실효성

시험 의상 두 개와 GLB 시편 두 개를 같은 화면에서 교체하면서 공용 제작 기반을 확인했다. 시험 데이터에 대한 결과이며 게임 콘텐츠의 아트 승인에 적용하지 않는다. 실전 작업은 요청부터 실제 게임 통합까지 같은 유형끼리 짝지어 [양식의 측정 항목](../templates/task.md#반복-제작-비용을-측정할-때)을 남긴다. 가속 배율을 계산할 실측 이전 기준은 아직 없다.

## 검증 및 다음 작업

- 로컬에서 문서 경로, Actions 문법, 빌드 재현성, 리그와 장착, Node 카엘 시나리오 및 Chromium 스튜디오를 확인했다. 지도 화면의 드래그 직후 터치 닫기와 기존 의상의 피부 간격은 [알려진 범위](../../knowledge/INDEX.md)에 기록했다.
- Pages 설정에서 게시 소스를 GitHub Actions로 전환한 뒤 [main 파이프라인](../../../.github/workflows/main-validation.yml)을 실행해 공개 URL과 배포 SHA를 확인한다.
- 다음 실제 제작 배치에서 기준 공수와 현재 공수를 수집한다. 시편만으로 생산 규모와 개발 속도 목표의 달성 여부를 판정할 수 없다.

## 후속 작업 (2026-11-24)

[영속 명세](../../core/INFRASTRUCTURE_SPEC.md), 카탈로그, 구조화 작업 기록, 링크/경로/중복 검사, PARTIAL 분류 및 다중 본 소매 파생 시편을 추가한다. 기존 게임 런타임 및 승인 형상은 변경하지 않는다. 순수 계약 테스트의 부정 사례를 실행했고 전체 Node/Chromium 결과는 새 커밋 CI에서 확인해야 한다. 실제 신상품 2~3벌·식생/자연물 10종의 미적 품질과 실제 월드 통합, 독립 세션 UI·동시 개발 실증, 게시 소스 전환 및 실측 가속은 남아 있다.

### 생태 배치 시제품

[생태 시제품 10종](../../references/ECOLOGY_PROTOTYPES.md)을 실제 GLB와 재현 가능한 공통 소스로 추가했다. 기존 카엘 게임에는 배치하지 않았다. 원본 기획 세부 조건·렌더 외형·LOD·실제 배치와 성능 검증은 남아 있다. 각 항목은 카탈로그에서 PROTOTYPED로 관리한다.

### 생성 재현성 회복 (2026-11-25)

`a6a262e` Actions Node 22.23.5에서 beach-morning-glory GLB byte 검증 실패. 기존 V8에서는 10종 모두 저장된 바이트와 동일. 별도 Node 22.16.0에서 동일 첫 모델의 생성 SHA 불일치 재현: sRGB pow의 마지막 자리와 퇴화 삼각형 법선이 다른 원인. 10nm 정점 스냅, 정규화 전 sliver 제외, 법선/색상 정밀도 고정 후 첫 모델 Node/V8 JSON·binary 해시 일치. 10종의 원래/새 삼각형 순서와 정점 비교: 남은 정점 최대 좌표 차이 5.96e-8m, 제거 면 최대 면적 8.31e-17m², 남은 법선 성분 최대 차이 2.62e-5. 외형 변경이나 아트 승인이 아니라 기존 시제품 생성 재현성 수리. 원본 GLB의 퇴화 면 검사 RED, 수정 10종 GREEN 및 같은 환경에서 재생성 byte 비교 통과. 전체 Node 22 CI 재검증 필요. 카탈로그 수치와 선례 갱신, 실제 게임 미배치 유지.
